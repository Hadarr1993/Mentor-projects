# המטבח של קאמפ פרדייז

כלי לניהול מטבח בפסטיבל לקבוצה גדולה — תכנון ארוחות צהריים וערב, חישוב כמויות אוטומטי
לפי מספר סועדים, רשימת קניות מרוכזת, שיבוץ תורנים, תכנון קרח וייצוא להדפסה.
כל הממשק בעברית, כיוון RTL.

האפליקציה עובדת **אופליין מלא** — היא נטענת ופועלת בלי קליטה, וזה לא פיצ'ר צדדי:
היא נועדה לשמש במדבר.

---

## הרצה מקומית

```bash
npm install
npm run dev
```

פיצ'רי ה-AI לא יעבדו ב-`npm run dev` או ב-`vite preview`, כי הם מחייבים את הפונקציות
של Vercel. הכפתורים יישארו פעילים ויציגו הודעה שמסבירה בדיוק את זה.
כדי להריץ גם אותן מקומית:

```bash
npx vercel dev
```

## פריסה ב-Vercel

חבר את הרפו ל-Vercel. הבנייה והפלט מוגדרים ב-`vercel.json`, אין מה לשנות.

### משתני סביבה

| משתנה | נדרש? | למה |
|---|---|---|
| `ANTHROPIC_API_KEY` | לפיצ'רי AI | זיהוי מנה מתמונה, יצירת מתכון מטקסט, הצעת הוראות הכנה |
| `CLAUDE_MODEL` | לא | ברירת מחדל `claude-sonnet-4-6`. אפשר לשנות בלי לגעת בקוד |
| `ANTHROPIC_WORKSPACE_ID` | רק למפתח מקושר-זהות | מפתח שנוצר מול משתמש ולא מול workspace נדחה בלי לציין באיזה workspace הבקשה פועלת. אפשר במקום זה פשוט ליצור מפתח מתוך Workspace ספציפי |
| `KV_REST_API_URL` | לשיתוף בענן | מגיע אוטומטית עם אינטגרציית Upstash |
| `KV_REST_API_TOKEN` | לשיתוף בענן | כנ"ל |

**המפתח של Anthropic לא מגיע לדפדפן.** כל הקריאות עוברות דרך `api/claude.js`.

לשיתוף בין מכשירים: ב-Vercel → Storage → Marketplace → Upstash Redis. החיבור מזריק
את שני משתני ה-KV אוטומטית. גם `UPSTASH_REDIS_REST_URL` / `_TOKEN` נתמכים.

**בלי אף אחד מהם האפליקציה עובדת מצוין** — פשוט מקומית בלבד, עם הודעה מסבירה בכל
מקום שנוגע בהם.

## שמירת נתונים

זה החלק שתוכנן ראשון ונבדק לפני שנבנה ממשק מעליו, כי הסיכון האמיתי הוא לאבד תכנון
של שבוע שלוש שעות לפני שיוצאים.

**המפתח `midburn-kitchen` קבוע ולא משתנה לעולם.** שינוי שלו מאפס את כל המשתמשים.

### שלוש ההגנות

1. **סכמה ממוספרת עם מיגרציות.** `SCHEMA_VERSION` ב-`src/state/schema.js`, ומערך
   `MIGRATIONS`. בטעינה רצות המיגרציות מהגרסה השמורה ואילך, ואז `deepMergeDefaults`
   מוזג ברירות מחדל **מתחת** לנתונים הקיימים. שדה חדש שנוסיף בעתיד מקבל ברירת מחדל;
   שום דבר קיים לא נדרס. יש בדיקה ייעודית שמוודאת בדיוק את זה.

2. **IndexedDB ולא localStorage.** בפועל ~930MB מול ~5MB. תמונת מתכון מטלפון היא
   3.4MB לפני כיווץ; עם localStorage היינו מגיעים למכסה ומתחילים להיכשל באמצע שמירה.
   כל תמונה מכווצת ל-600px / JPEG 0.7 → כ-24KB.

3. **JSON פגום לא מאפס.** הוא נשמר בצד תחת `midburn-kitchen__corrupt`, האפליקציה
   עולה מברירות מחדל, ומוצג באנר עם אפשרות להוריד עותק.

### להוסיף שדה בלי לשבור נתונים

1. הוסף אותו ל-`makeDefaults()`.
2. אם הוא דורש חישוב מנתונים קיימים — העלה את `SCHEMA_VERSION` והוסף מיגרציה תואמת.
3. אם הוא סתם שדה חדש עם ברירת מחדל — לא צריך כלום, המיזוג מטפל בזה.

### שכבת האחסון

`src/state/storage.js` חושף `get/set/delete(key, shared)` — בדיוק החתימה של
`window.storage` בסביבת artifacts של claude.ai. אם `window.storage` קיים הוא מנצח,
אחרת IndexedDB, ואם גם הוא חסום (גלישה פרטית) — זיכרון בלבד עם באנר אזהרה קבוע.
כך אותו קוד רץ גם כאן וגם כ-artifact.

### שיתוף עם הצוות

**השרת הוא המקור היחיד לאמת.** המכשיר מחזיק מטמון של המסמך האחרון שהשרת נתן,
ותור של עריכות שטרם אושרו. מה שמוצג הוא המטמון עם התור מעליו — ולכן עריכה נראית
מיד, והמסך עובד גם בלי קליטה.

| פעולה | מה קורה |
|---|---|
| הצטרפות למחנה | **קריאה** של המסמך. אין מיזוג ואין כיוון. |
| עריכה | מוצגת מיד, נכנסת לתור, נדחפת ברקע |
| בלי קליטה | קוראים מהמטמון, התור ממתין |
| עדכון של חבר צוות | מגיע לבד — סקר אדפטיבי, בלי ללחוץ כלום |

**אין מתג אישי/משותף.** קוד המחנה הוא הגבול; מי שרוצה מרחב פרטי פשוט מחזיק קוד
משלו.

**אין מיזוג של שני מסמכים, וזה מכוון.** כל עריכה נכתבת כטרנספורמציה טהורה של
המסמך שהיא מקבלת — `(doc) => ({ ...doc, recipes: { ...doc.recipes, [id]: mine } })`.
הרצה חוזרת שלה מעל מסמך חדש יותר של חבר צוות משמרת את כל מה שהוא שינה ומחילה רק
את מה שהמכשיר הזה שינה. גרסה קודמת מיזגה שני מסמכים שלמים לפי חותמות זמן, וזה
מה שאיפשר לברירות מחדל טריות לדרוס עבודה אמיתית — מסמך שנוצר היום נשא חותמות
חדשות יותר. **החזרת מיזוג כזה תחזיר את הבאג.**

הסקר **אדפטיבי**: כ-5 שניות אחרי פעילות, מאט עד ~60 שניות כשהמסך שקט, ורק כשהלשונית
גלויה ויש רשת. `GET` עם `?since=<rev>` מחזיר `{ unchanged: true }` כשאין שינוי,
כדי לא לשרוף את מכסת הפקודות של Upstash.

**"מי אני במכשיר הזה"** נשמר ב-`midburn-kitchen__device` ואינו מסונכרן — `settings`
נדרס בין מכשירים, ושם כל טלפון היה מקבל את השם של מי שכתב אחרון.

> ⚠️ כל מי שמחזיק בקוד המחנה יכול לקרוא ולכתוב. אין אימות. שתף רק עם הצוות.

### עיצוב

פלטת "שקיעת מדבר" עם מלאכה בסגנון אפל:

- **קפיצים ב-`requestAnimationFrame`** במקום CSS transitions לכל מה שנגרר. קפיץ מתחיל
  מהערך שעל המסך, ולכן אפשר לתפוס אלמנט באמצע תנועה ולהפוך כיוון בלי קפיצה.
- **בורר הימים נגרר 1:1** עם Pointer Events, היסטוריית מהירות, השלכת תנופה
  ו-rubber-banding בקצוות במקום עצירה קשה.
- פידבק על pointer-down ולא על click; טאב-בר שקוף עם `backdrop-filter`;
  tracking טיפוגרפי לפי גודל; הפרדה בין אזורים דרך משטח וצל ולא קווי 1px.
- כיבוד `prefers-reduced-motion`, `prefers-reduced-transparency` ו-`prefers-contrast`.

**אין אמוג'ים בממשק.** כל האייקונים הם Lucide, רשומים ב-`src/components/Icon.jsx`.
שום קובץ אחר לא מייבא מספריית האייקונים, כך שהחלפת סט היא שינוי בקובץ אחד.
`scripts/gen-export-icons.mjs` מחלץ את אותם אייקונים כ-SVG גולמי עבור הקבצים
המיוצאים, כדי שיישארו עצמאיים לחלוטין.

## חישוב הכמויות

כמות = `כמות לאדם × סועדים בארוחה × (1 + רזרבה%)`

- ברירת מחדל: 50 סועדים, רזרבה 12%. אפשר לדרוס מספר סועדים לכל ארוחה בנפרד.
- תוספות נספרות באותו מספר סועדים כמו המנה העיקרית.
- מצרכים זהים (שם + יחידה) מתאחדים לשורה אחת בכל רשימות הקניות.
- תצוגה: גרם ≥1000 → ק"ג, מ"ל ≥1000 → ליטר, יחידות מעוגלות תמיד כלפי מעלה.
- רשימת הקניות = ארוחות + תוספות + (ארוחת בוקר × אנשים × ימים) + מזווה קבוע
  + פריטים שהוספת ידנית.
- מזווה קבוע כולל **4 ליטר מים לאדם ליום**.

### פריטים חופשיים

כל השאר ברשימה נגזר ממתכון ומוכפל במספר הסועדים. לפריטים שהמטבח צריך אבל אף אחד
לא אוכל — אלומיניום, שקיות אשפה, בלון גז — יש כפתור **"פריטים שהוספת"** בראש
לשונית הקניות, עם בורר איך לחשב את הכמות:

| מצב | חישוב | מתי |
|---|---|---|
| **כמות קבועה** (ברירת מחדל) | הכמות כפי שהיא | 2 גלילי אלומיניום נשארים 2 |
| **לפי אדם** | × סועדים × רזרבה | כוס לכל אחד |
| **לפי אדם ליום** | × סועדים × ימים × רזרבה | חטיף יומי |

פריט חופשי בשם ויחידה זהים למצרך ממתכון מתאחד איתו לשורה אחת, כמו כל שאר
המקורות.

התאריכים נגזרים מ-`startDate` ולא מקודדים קשיח — שינוי התאריכים בהגדרות פשוט עובד.
